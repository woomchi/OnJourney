# 네이버 지도 API React UX 최적화 가이드

리액트(React) 환경에서 네이버 지도의 렌더링 부하와 깜박임을 잡고, 동적 패딩 및 오프셋 이동을 부드럽게 구현하기 위한 핵심 수칙입니다.

## 1. 지도 인스턴스 독립 (Re-render 차단)

지도를 감싸는 컴포넌트가 불필요하게 다시 그려지지 않도록 상태(State) 관리를 완전히 분리하는 것이 가장 중요합니다.

* **`useRef` 활용:** 최초 1회 마운트 시 `new naver.maps.Map()`으로 생성한 지도 객체는 `useState`가 아닌 `useRef`에 저장하여 생명주기를 영구적으로 보존합니다.
* **명령형 업데이트:** 패딩이나 중심 좌표가 바뀔 때 지도가 포함된 컴포넌트를 리렌더링하는 대신, `useEffect` 안에서 `useRef`에 담긴 지도 인스턴스의 내장 함수를 직접 호출합니다.

## 2. UI 애니메이션과 지도 조작의 완전한 분리

동적 패딩(오프셋)을 매 프레임마다 계산하여 지도에 주입하면 브라우저 렌더링 큐가 밀려 심각한 렉과 깜박임이 발생합니다.

* **동적 UI는 CSS로 전담:** 사이드바나 바텀시트가 열리고 닫히는 애니메이션은 React의 상태 변화에 따른 즉각적인 렌더링 대신, CSS의 `transition`과 `transform`을 활용해 부드럽게 처리합니다.
* **실시간 동기화 금지:** 패널이 움직이는 시간(예: 0.3초) 동안 지도의 중심축을 실시간으로 맞추려 하지 마세요.

## 3. 타이밍 기반의 오프셋 호출 패턴

복잡한 디바운스(Debounce) 로직 대신, **'UI 애니메이션 종료 후 1회 호출'** 패턴을 적용하여 구현 난이도를 낮추고 성능을 확보합니다.

1. **상태 변경:** 사용자가 사이드바 열기 버튼을 클릭하여 UI State가 변경됩니다.
2. **UI 애니메이션 실행 (CSS):** 사이드바가 정해진 시간(예: 300ms) 동안 화면에 등장합니다.
3. **지연 및 호출:** CSS 애니메이션이 끝나는 시점(`setTimeout(..., 300)` 또는 DOM의 `onTransitionEnd` 이벤트)에 맞추어 딱 한 번 오프셋을 계산합니다.
4. **지도 이동 (`panBy`):** `map.panBy(new naver.maps.Point(이동할 X, 이동할 Y), { duration: 300 })`을 호출하여 가려진 영역만큼 지도를 부드럽게 밀어줍니다.

## 4. `fitBounds`를 활용한 동적 패딩 정렬 (마커 그룹 기준)

단순히 화면을 미는 것(`panBy`)이 아니라, 지도 위의 특정 마커들이 모두 보이도록 줌과 중심을 동시에 조절해야 한다면 `fitBounds`의 마진 옵션을 활용합니다.

* **여백(Margin) 활용:** `map.fitBounds(bounds, { margin: { left: 300, top: 50, right: 50, bottom: 50 } })` 형태로 호출합니다.
* **동적 적용:** 사이드바가 열려있을 때만 `margin.left`에 300(사이드바 너비)을 주고, 닫혀있을 때는 0을 주어 남은 실제 시야 영역의 중앙에 마커들이 정확하고 예쁘게 정렬되도록 구성합니다.

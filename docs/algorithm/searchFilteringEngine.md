# 카카오 API 기반 복합 검색 엔진 설계서

## 1. 알고리즘 목표
- 범용 검색의 신뢰성을 확보하면서도 랜드마크(예: 부산역) 누락 현상을 방지한다.
- 현재 지도의 중심 좌표(x, y)와 반경(radius)을 기준으로 사용자 컨텍스트를 반영한다.
- 단순한 이름 매칭만으로는 놓칠 수 있는 결과를 보완하기 위해, 의도 기반 매칭과 다중 파이프라인 병합을 함께 사용한다.

---

## 2. 핵심 원칙
검색 결과는 단순히 이름만 비교하는 방식이 아니라, 다음 순서로 판단한다.

1. **완전 일치:** 검색어와 장소명이 거의 동일한 경우를 가장 우선적으로 본다.
2. **의도 기반 매칭:** 검색어의 의미와 장소의 카테고리가 잘 맞는 경우를 다음으로 본다.
3. **부분 매칭:** 이름에 검색어가 포함되지만, 의도는 덜 명확한 경우를 나중에 본다.
4. **거리 보정:** 마지막으로 위치와 거리 정보를 반영해 최종 순서를 결정한다.

즉, "정확한 이름"을 우선하고, 그다음으로 "사용자가 원하는 종류의 장소"를 반영하며, 마지막으로 "가까운 위치"를 고려한다.

---

## 3. 검색 처리 파이프라인 (4단계)

### Phase 1: 쿼리 분석 및 컨텍스트 바인딩
사용자 입력어와 현재 지도 상태를 분석해 검색 조건을 분리한다.

1. **지명/행정구역 분리:** 검색어 내 행정구역 키워드(예: 수원시, 망포동) 추출한다.
2. **랜드마크 판별:** 검색어 끝에 역, 터미널, 공항, 시청 등의 키워드가 포함되었는지 확인한다.
3. **지도 컨텍스트:** 현재 지도의 중심 좌표(x, y)와 줌 레벨에 따른 탐색 반경(radius)을 설정한다.

### Phase 2: 멀티 파이프라인 검색 (Multi-Pipeline)
랜드마크 보장과 주변 장소 탐색을 동시에 수행하기 위해 두 개의 검색 경로를 병렬로 사용한다.

- **Pipeline A (정확도/랜드마크 보장형)**
  - 파라미터: query, sort=accuracy
  - 특징: 중심 좌표나 반경 제한을 두지 않거나 매우 넓게 설정해, 이름이 정확히 일치하는 주요 랜드마크가 결과셋에 포함되도록 보장한다.

- **Pipeline B (중심 좌표 기반 주변 탐색형)**
  - 파라미터: query, x, y, radius, sort=distance
  - 특징: 현재 지도 중심을 기준으로 반경 내의 실제 주변 장소를 수집한다.

이 방식은 이름이 정확한 랜드마크와, 실제 사용자 주변의 장소를 동시에 확보하는 데 유리하다.

### Phase 3: 결과 병합 및 필터링
두 파이프라인의 결과를 하나로 합치고, 사용자 컨텍스트와 검색 의도에 맞춰 노이즈를 제거한다.

1. **중복 제거:** API 결과의 id를 기준으로 중복 데이터를 병합한다.
2. **의도 기반 필터링:** 검색어의 의미와 장소의 categoryName이 잘 맞는지 확인한다.
3. **행정구역 필터링:** 검색어나 필터 조건에 포함된 지역 외의 결과는 제거한다.

이 단계는 단순히 많은 결과를 모으는 것이 아니라, “의도에 맞는 결과만 남긴다”는 역할을 한다.

### Phase 4: 하이브리드 스코어링 (Tier + Distance)
필터링된 결과에 점수를 부여해 최종 순서를 정한다.

1. **Tier 부여 (기본 점수)**
   - **Tier 1 (1000점):** 검색어와 장소명(place_name)이 완벽히 일치하는 경우
   - **Tier 2 (700점):** 장소명은 다르지만, 카테고리(category_name)가 검색어의 의도 패턴에 부합하는 경우
   - **Tier 3 (300점):** 장소명에 검색어가 단순 포함된 경우

2. **도메인 가중치 부여 (Bonus)**
   - 여행, 관광, 음식, 의료 등 서비스 성격에 맞는 카테고리에는 추가 점수(+150점)를 부여할 수 있다.

3. **거리 감쇠 페널티 (Distance Decay)**
   - 중심 좌표로부터 멀어질수록 점수를 차감한다.
   - 예: 거리 100m당 10점 감점
   - 공식: 최종 점수 = Tier 점수 + 가중치 - 거리 페널티
   - 단, 과도한 감점을 막기 위해 최대 차감 한도(threshold)를 둔다.

---

## 4. 정렬 우선순위 및 동점자 처리
모든 스코어링이 끝난 결과는 다음 기준으로 정렬한다.

1. **1순위:** 하이브리드 스코어링 최종 점수가 높은 순
2. **2순위:** 점수가 같다면 중심 좌표로부터의 거리(distance)가 가까운 순
3. **3순위:** 거리까지 같다면 카카오 API 본연의 정확도 순서

이렇게 정리하면, 단순한 이름 일치뿐 아니라 사용자의 실제 의도와 위치 맥락을 함께 반영할 수 있다.

## 5. 검증 시나리오

- [ ] **"수원역" 검색 시:** Pipeline A를 통해 수원역 본체가 Tier 1로 높은 점수를 받아, 주변의 다른 유사 상호명보다 우선 노출되는가?
- [ ] **"망포동 감성 카페" 검색 시:** 행정구역 필터링이 정상 동작하고, 이름에 '카페'가 없어도 카테고리 기반으로 적합한 장소가 높은 점수를 받는가?
- [ ] **거리 감쇠 역전 확인:** 5km 밖의 완전 일치 장소보다, 500m 이내의 의도 매칭 장소가 최종 점수에서 우위를 점해 상위 노출되는가?
- [ ] **랜드마크 누락 방지:** 검색어가 랜드마크를 포함할 때, 정확한 장소명이 결과셋에 포함되는가?

---

## 6. 구현 관점에서의 요약
실제로는 다음 두 가지 방식이 함께 작동한다고 이해하면 된다.

- **검색 엔진 관점:** 여러 파이프라인을 함께 사용해 결과를 더 안정적으로 확보한다.
- **사용자 경험 관점:** 완전 일치 → 의도 기반 매칭 → 부분 매칭 → 거리 보정 순으로 결과를 정리한다.

이 두 흐름을 함께 쓰면, 정확도와 직관성 둘 다 높일 수 있다.

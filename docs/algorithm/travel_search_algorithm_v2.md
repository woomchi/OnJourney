# 여행 지도 서비스 장소 검색 랭킹 알고리즘 설계서

## 1. 개요 (Overview)
본 문서는 카카오 로컬 API(키워드 검색 API)를 원천 데이터로 활용하되, **여행 도메인**에 최적화된 검색 결과를 제공하기 위해 자체적인 복합 점수(Composite Score)를 부여하여 결과를 재정렬(Re-ranking)하는 알고리즘 파이프라인을 정의합니다.

## 2. 데이터 파이프라인 (Pipeline)
1. **데이터 수집 (Fetch):** 카카오 키워드 검색 API (`/v2/local/search/keyword.json`) 호출 시 `sort=accuracy` 옵션을 주어 1차 후보군 데이터(최대 45개)를 가져옵니다.
2. **필터링 (Filter):** 여행과 무관한 노이즈 카테고리를 제외합니다.
3. **점수화 (Scoring):** 추출된 장소마다 '카테고리 가중치', '거리 감쇠 점수', '내부 인기도'를 합산하여 최종 점수를 산출합니다.
4. **정렬 및 반환 (Sort & Return):** 최종 점수 기준 내림차순 정렬 후 상위 N개(예: 15~20개)를 클라이언트에 반환합니다.

---

## 3. 최종 점수 산출 공식 (Composite Score Formula)

각 장소의 최종 랭킹 점수($S_{total}$)는 다음 공식을 통해 산출됩니다.

$$ S_{total} = (S_{cat} \times W_{cat}) + (S_{dist} \times W_{dist}) + (S_{pop} \times W_{pop}) $$

*   $S_{cat}$: 카테고리 적합도 점수 (0.0 ~ 1.0)
*   $S_{dist}$: 거리 감쇠 점수 (0.0 ~ 1.0)
*   $S_{pop}$: 서비스 자체 인기도 점수 (0.0 ~ 1.0) - 리뷰 수, 찜 횟수 등 정규화
*   $W_{cat}, W_{dist}, W_{pop}$: 각 항목의 중요도를 결정하는 가중치 (합은 1.0 또는 100)
    *   *추천 설정값: $W_{cat} = 0.4$, $W_{dist} = 0.4$, $W_{pop} = 0.2$*

---

## 4. 카테고리 가중치 ($S_{cat}$) 설계

카카오 API의 `category_group_code`를 기준으로 여행 목적성에 따라 등급(Tier)을 나누어 가점을 부여합니다.

| 분류 | 카테고리 코드 (Kakao API) | 점수 ($S_{cat}$) | 설명 |
| :--- | :--- | :--- | :--- |
| **Tier 1** | `AT4`(관광명소), `AD5`(숙박), `CT1`(문화시설) | **1.0** | 여행의 핵심 목적지 |
| **Tier 2** | `FD6`(음식점), `CE7`(카페), `PK6`(주차장) | **0.8** | 여행 중 반드시 방문하는 편의/식음료 |
| **Tier 3** | `CS2`(편의점), `PM9`(약국), `MT1`(대형마트), `OL7`(주유소) | **0.4** | 필요시 검색하는 보조 편의시설 |
| **제외** | `AG2`(부동산), `PO3`(공공기관), `SC4`(학교) 등 기타 | **0.0** (필터링) | 여행과 무관한 데이터 노이즈 제거 |

---

## 5. 거리 감쇠 점수 ($S_{dist}$) 설계 - 가우시안 감소 적용

단순 선형 비례가 아닌, 가까운 거리는 후하게 주고 먼 거리는 급격히 깎는 **가우시안 감소(Gaussian Decay)** 함수를 적용합니다. 사용자의 이동 수단(도보 vs 차량)에 따라 $scale$ 값을 동적으로 변경합니다.

$$ S_{dist} = e^{- \frac{d^2}{2 \cdot scale^2}} $$

*   **$d$ (거리):** 사용자의 현재 위치와 장소 간의 거리 (단위: km). API 응답의 `distance` 필드 활용.
*   **$scale$ (기준 반경):** 점수가 약 0.606($e^{-0.5}$)으로 떨어지는 기준 거리.
    *   **도보 모드:** `scale = 1.0` (1km 밖이면 점수가 크게 하락)
    *   **차량 모드 (제주도 등):** `scale = 5.0` (5km 내외는 큰 페널티 없음)

---

## 6. 핵심 알고리즘 처리 흐름 (Core Algorithm Logic)

코드 대신, 시스템이 API 응답을 받아 최종 결과를 클라이언트에 전달하기까지의 핵심 논리 흐름을 단계별로 정의합니다.

### Step 1. 데이터 수신 및 반복 처리 시작 (Data Intake)
*   카카오 키워드 검색 API로부터 최대 45개의 장소 객체 리스트를 수신합니다.
*   반환할 최종 장소 리스트(빈 배열)를 초기화하고, 수신된 각 장소 객체에 대해 순차적으로 점수 평가(Step 2~5)를 시작합니다.

### Step 2. 카테고리 적합도 평가 (Category Scoring & Filtering)
*   장소 객체의 `category_group_code`를 확인합니다.
*   미리 정의된 Tier 테이블과 대조하여 **$S_{cat}$ 점수(1.0, 0.8, 0.4)**를 부여합니다.
*   만약 카테고리가 Tier 1~3에 속하지 않는다면(예: 부동산, 학교 등), 해당 장소에 대한 평가를 즉시 중단(Drop)하고 다음 장소로 넘어갑니다. (노이즈 필터링)

### Step 3. 거리 기반 감쇠 점수 계산 (Distance Decay Scoring)
*   장소 객체의 `distance` 값(미터 단위)을 킬로미터(km) 단위로 변환합니다.
*   사용자가 현재 설정한 '이동 수단(도보 또는 차량)' 상태를 확인하여 **기준 반경($scale$)** 값을 결정합니다.
*   가우시안 감소 공식($e^{-(d^2)/(2 \cdot scale^2)}$)에 $d$와 $scale$을 대입하여 **$S_{dist}$ 점수(0.0 ~ 1.0)**를 계산합니다.

### Step 4. 내부 인기도 데이터 결합 (Popularity Scoring)
*   해당 장소의 고유 ID(`id`)를 키값으로 사용하여, 서비스 자체 데이터베이스(또는 캐시)를 조회합니다.
*   조회된 사용자 행동 지표(찜 횟수, 조회수, 리뷰 수 등)를 0.0에서 1.0 사이의 값으로 정규화하여 **$S_{pop}$ 점수**를 산출합니다.
*   만약 내부 데이터가 없는 신규/비인기 장소라면 기본값(예: 0.1 또는 0.0)을 부여합니다.

### Step 5. 복합 점수 산출 및 정렬 (Total Scoring & Sorting)
*   계산된 $S_{cat}$, $S_{dist}$, $S_{pop}$ 에 각각 지정된 가중치(예: 0.4, 0.4, 0.2)를 곱하여 모두 더합니다 ($S_{total}$).
*   산출된 $S_{total}$ 값을 해당 장소 객체의 새로운 속성으로 추가하고, 필터링을 통과한 장소 리스트에 저장합니다.
*   모든 장소에 대한 평가가 끝나면, **$S_{total}$ 값을 기준으로 리스트를 내림차순 정렬**합니다.
*   정렬된 리스트에서 상위 N개(예: 20개)만 절삭하여 클라이언트 지도 화면에 렌더링하도록 반환합니다.

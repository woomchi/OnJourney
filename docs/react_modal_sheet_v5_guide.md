# 📘 react-modal-sheet v5 엄격한 규칙 가이드

`react-modal-sheet` 라이브러리가 버전 5(v5)로 업데이트되면서 바텀 시트의 위치를 제어하는 `snapPoints` 속성에 **매우 엄격하고 깐깐한 규칙(Breaking Change)**이 도입되었습니다. 이 규칙을 지키지 않으면 물리 엔진이 렌더링을 중단하고 치명적인 런타임 에러를 발생시킵니다.

향후 바텀 시트를 수정하거나 추가할 때 반드시 아래의 규칙을 준수해야 합니다.

---

## 🚨 핵심 규칙 3가지

### 1. 무조건 오름차순(Ascending Order) 정렬
이전 버전에서는 `[800, 400, 100]`처럼 픽셀 값을 내림차순으로 넣었지만, **v5부터는 반드시 값이 작은 것부터 큰 것 순서(오름차순)로 배열**되어야 합니다.
- ❌ 잘못된 예: `[800, 370, 136]` (런타임 에러 발생)
- ✅ 올바른 예: `[0, 136, 370, 1]`

### 2. 첫 번째 값은 무조건 `0`
배열의 맨 처음 값(인덱스 0)은 바텀 시트가 **완전히 닫힌 상태를 의미하는 `0`**이어야 합니다.
만약 `0`을 넣지 않으면 라이브러리가 강제로 맨 앞에 `0`을 끼워 넣으며 경고(Warning)를 발생시킵니다. 
바텀 시트가 닫히지 않고 최소 높이를 유지하게 만들고 싶다면, `onClose`나 `onSnap` 이벤트에서 닫힘(인덱스 0)이 감지되었을 때 강제로 최소 높이(인덱스 1)로 튕겨내도록 방어 코드를 작성해야 합니다.

### 3. 마지막 값은 무조건 `1`
배열의 맨 마지막 값은 바텀 시트가 **최대 높이로 열린 상태를 의미하는 `1` (100% 비율)**이어야 합니다.
마찬가지로 `1`을 넣지 않으면 라이브러리가 배열 맨 끝에 `1`을 강제로 추가합니다.

---

## 💡 값의 단위: 픽셀(px) vs 비율(multiplier)

v5에서는 배열 내부에 들어가는 숫자의 크기에 따라 단위를 다르게 해석합니다.

- **`0` ~ `1` 사이의 값:** 시트 최대 높이에 대한 **비율(%)**로 계산됩니다.
  - 예: `0.4` = 시트 높이의 40% 지점
- **`1` 초과의 값:** 화면 바닥(Bottom)에서부터의 **절대 픽셀(px)**로 계산됩니다.
  - 예: `370` = 바닥에서 370px 지점
- **음수 값:** 시트 최대 높이에서 차감한 **절대 픽셀(px)**로 계산됩니다.
  - 예: `-100` = 최대 높이에서 100px 아래 지점

## 🛠 실전 적용 패턴 (OnJourney 프로젝트 기준)

현재 우리 프로젝트(`JourneySidebar`, `RouteGuidePanel` 등)에는 바텀 시트가 완전히 닫히면 안 되고 항상 최소한의 정보(예: 84px 높이)를 보여주어야 하는 요구사항이 있습니다. 이를 위한 표준 패턴은 다음과 같습니다.

```tsx
// 1. 오름차순으로 스냅 포인트 정의 (0과 1 필수 포함)
const snapPoints = [0, 84, 370, 1]; // [닫힘, 최소, 기본, 최대]

<Sheet
  isOpen={true} // 항상 열려 있도록 설정
  snapPoints={snapPoints}
  initialSnap={2} // 초기 렌더링 시 기본 높이(370px)로 설정
  onClose={() => {
    // [방어 코드] 스와이프로 완전히 닫으려 할 때 최소 높이로 원복
    if (sheetRef.current) sheetRef.current.snapTo(1); 
  }}
  onSnap={(snapIndex) => {
    if (snapIndex === 0) {
      // [방어 코드] 닫힘 지점(0)에 도달하면 최소 높이(1)로 강제 이동
      if (sheetRef.current) sheetRef.current.snapTo(1);
      setSnap('84px');
    }
    else if (snapIndex === 1) setSnap('84px');
    else if (snapIndex === 2) setSnap('370px');
    else if (snapIndex === 3) setSnap(1); // 1 = 전체 화면
  }}
>
  ...
</Sheet>
```

> [!WARNING]
> 화면 높이(`window.innerHeight`)를 직접 계산해서 픽셀 값을 주입할 때, 특정 환경(예: 키보드가 올라온 모바일 브라우저)에서는 계산된 화면 높이 픽셀값이 기본 스냅 포인트(예: 370px)보다 작아져 오름차순 규칙이 깨질 수 있습니다. 
> 
> 따라서 픽셀값으로 최대 높이를 계산할 때는 `Math.max(계산된_최대_높이, 기본_스냅_포인트 + 10)` 과 같이 **오름차순이 무조건 보장되도록 안전장치**를 걸어주어야 합니다.

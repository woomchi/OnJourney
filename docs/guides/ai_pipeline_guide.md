# OnJourney AI 협업 파이프라인 및 코딩 컨벤션

> **작성 목적:** 
> AI(Antigravity)와 개발자 간의 효율적인 협업을 통해 기술 부채를 방지하고, 유지보수가 용이한 최적의 코드를 작성하기 위한 가이드라인입니다. 본 문서는 AI의 '바퀴 재발명(하드코딩)'을 막고 기존 생태계를 최대한 활용하는 데 목적이 있습니다.

---

## 1. 기본 원칙 (Core Principles)

*   **기존 생태계 최우선 도입:** 검증된 라이브러리(npm, React, Tailwind 생태계 등)나 패턴이 존재한다면, 직접 커스텀 로직을 구현하는 것을 지양합니다.
*   **사전 설계 컨설팅 필수:** AI에게 즉각적인 코드 생성을 요구하기 전, 반드시 "어떤 방식으로 구현할 것인가"에 대한 아키텍처 및 라이브러리 제안을 먼저 받습니다.
*   **컨텍스트 제공의 의무:** AI가 프로젝트 환경을 정확히 이해할 수 있도록, 지시 전 관련된 `package.json` 의존성 목록과 기존 코드를 묶어서 일괄 제공합니다.

---

## 2. AI-개발자 4단계 협업 워크플로우

### Step 1: 컨텍스트 동기화 (Sync)
새로운 작업 시작 전, 현재 프로젝트의 상태와 사용 가능한 도구를 AI에게 인지시킵니다.
*   **Action:** `package.json`의 `dependencies` 목록과 수정/참고할 파일의 전체 코드를 제공.

### Step 2: 기술 탐색 및 제안 (Audit)
AI가 코드를 짜기 전, 목표 달성을 위한 최적의 도구와 구현 방식을 분석하게 합니다.
*   **Action:** AI에게 "직접 구현하지 말고 최적의 라이브러리와 방식을 2~3가지 제안하라"고 지시.

### Step 3: 명세 기반 코드 생성 (Generate)
Step 2에서 결정된 방식을 바탕으로 실제 코드를 구현합니다.
*   **Action:** 확정된 라이브러리와 설계 명세를 주고, "바퀴 재발명 금지" 조건을 명시하여 코드 작성을 요구.

### Step 4: 예외 상황 및 성능 검증 (Review)
작성된 코드의 안정성을 검증합니다.
*   **Action:** 모바일 환경, SSR, 비동기 상태 등에서 발생할 수 있는 Edge Case와 렌더링 성능 최적화(메모이제이션 등) 방안을 AI에게 검토 지시.

## 3. 실전 프롬프트 템플릿 (Prompt Templates)

아래 템플릿의 `[ ]` 괄호 친 부분을 상황에 맞게 수정하여 AI에게 전달합니다.

### 📝 A. 신규 기능 개발 시
```text
[목표]
새로운 [기능 이름/설명]을 구현하려고 해.

[컨텍스트]
아래는 현재 우리 프로젝트의 package.json 의존성 목록이야.
(여기에 package.json 붙여넣기)

[요구사항]
이 기능을 처음부터 직접 하드코딩하지 마. 
현재 설치된 라이브러리나 npm의 최신 표준 라이브러리 중 가장 적합한 도구를 찾아, 
이를 활용한 최적의 구현 방식 2가지를 장단점과 함께 제안해 줘. 
내가 방식을 선택하기 전까지는 코드를 작성하지 마.

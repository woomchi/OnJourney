# [Project Context] On-Journey (다중 경유지 경로 최적화 서비스)

## 1. Service Overview & Philosophy
* **서비스명:** 온저니 (On-Journey)
* **브랜드 철학 및 슬로건:** "당신의 모든 이동이 온전히, 여정이 되도록."
  * 한국어 '온전히(조금도 부족함 없이 완벽하게)'와 영어 'On-Journey(여정 중에)'의 언어유희입니다. 여행이라는 단어가 주는 무거움과 "무언가를 해야 한다"는 강박을 벗어던지고, 문 밖을 나서는 순간부터 목적지에 닿기까지의 모든 평범한 이동을 하나의 소중한 여정으로 대한다는 철학을 담고 있습니다.
* **서비스 개요:** 사용자가 추가한 다수의 방문지를 바탕으로 이동 시간과 비용을 최소화하는 구간별 최적 경로 이동솔루션입니다. 방문하고자 하는 장소(n개)를 자유롭게 추가하고 직관적인 드래그 앤 드롭(Drag & Drop)으로 순서를 조정하면, 구간별 최적 경로와 이동 수단을 자동으로 생성하여 완벽히 개인화된 이동 경험을 제공합니다. 사용자가 추가하고 조정한 장소 순서는 온전히 여정의 의도로 보존되도록 합니다.

---

## 2. Target Use Cases
1. **🎒 통학 및 출퇴근 (반복적인 일상 경로)**
   * **문제:** 매일 같은 정류장/역을 이용하지만, 실시간 도착 정보를 보기 위해 매번 앱을 켜서 검색해야 함.
   * **해결:** 출발지와 도착지(학교/직장) 및 자주 타는 교통수단을 '여정'으로 저장. 향후 홈 화면 위젯 등을 통해 앱 실행 없이도 클릭 한 번으로 즐겨찾는 수단의 실시간 이동 시간 및 도착 정보를 즉시 확인.
2. **✈ 뚜벅이 여행객 (복잡한 다중 경로)**
   * **문제:** 자차가 없는 여행객은 낯선 지역에서 여러 관광지를 방문할 때마다 매번 지도 앱을 켜서 대중교통 경로를 새로 검색해야 함.
   * **해결:** 방문할 여러 경유지를 한 번에 저장하면 구간별 최적 경로를 하나의 여정 처럼 한 번에 제공함. A에서 B로 갈 때는 몇 번 버스를 타는지 등 '교통수단 정보'까지 함께 저장되어, 여행 중 클릭 몇 번만으로 다음 목적지로 이동할 준비를 마칠 수 있음.

## 3. Core Features (MVP)

### 여정 생성 기능 (구현 완료)
- 여정명, 기본 이동 수단, 날짜 선택을 통해 여정 생성
- 여정명: 사용자가 여정을 설명하는 텍스트 입력
- 기본 이동 수단: 대중교통 / 차량 / 도보
- 여정 날짜 선택: 달력 컴포넌트를 통해 여정 날짜 선택

### 여정 정보 수정 기능 (구현 완료)
- 여정명, 기본 이동 수단, 날짜를 수정할 수 있는 모달 UI (`EditJourneyModal`) 구현
- 수정 시 경로 데이터 자동 재계산 트리거

### 장소 검색 및 추가 (구현 완료)
- 상단 검색바를 통해 네이버 장소 검색 API를 연동하여 장소 검색 및 추가
- 여정이 선택되지 않은 상태(목록 화면)에서도 검색 가능하며, 추가할 여정을 선택할 수 있는 모달 UI 제공

### 구간별 실시간 이동 정보 제공 (✅ 구현 완료 — API 연동)
- **대중교통:** ODsay 대중교통 경로탐색 API (`searchPubTransPathT`) 실시간 연동 완료
  - 경로별 소요시간, 요금, 환승 정보, 노선명, 탑승/하차 정류장 정보 제공
  - 버스/지하철 노선별 색상 자동 매핑 (간선: 파란색, 지선: 초록색, 광역: 빨간색, 순환: 노란색 등)
  - `loadLane` API를 통한 상세 궤적(폴리라인) 좌표 획득 및 지도 렌더링
  - 도보 검색 반경 필터링 적용 (출발·도착 15분, 환승 10분, 총 도보 25분 초과 경로 제외)
  - API 429 에러 대비 Exponential Backoff 재시도 로직 내장
  - 출·도착지 700m 이내 등 에러 발생 시 차량 기반 Fallback 경로 자동 생성
- **차량:** 네이버 Directions 5 API 실시간 연동 완료
  - `trafast`(실시간 빠른길) / `traoptimal`(실시간 최적길) / `traavoidtoll`(무료 도로) 3가지 경로 옵션 제공
  - 톨비, 택시 요금, 주행 거리, turn-by-turn 가이드 정보 제공
  - 상세 도로 경로 폴리라인(path) 지도 렌더링 지원
  - API 실패 시 Haversine 기반 Fallback 계산 (예상 소요시간, 택시 요금 추정)
- **도보/자전거/킥보드:** 직선거리 기반 추정 소요시간 및 비용 제공
  - 도보 평균 4.5km/h, 자전거 15km/h, 킥보드 18km/h 기준 계산
  - 킥보드 요금: 기본 1,000원 + 분당 150원 추정
- **장거리 노선 (기차/시외버스):** ODsay API 연동 완료
  - KTX, SRT, 무궁화호, ITX-새마을 등 기차 경로 및 고속/시외버스 경로 표시
  - 예매 링크 자동 생성 (SRT → etk.srail.kr, 코레일 → letskorail.com, 고속버스 → kobus.co.kr, 시외버스 → bustago.or.kr)
  - 장거리 구간 요금 추정(`isFareEstimated`) 및 구간 식별(`isIntercity`) 플래그 지원

### 실시간 버스/지하철 도착 정보 (✅ 구현 완료 — API 연동)
- **지하철 실시간 도착 정보:**
  - 서울시 실시간 지하철 도착 API (`swopenAPI.seoul.go.kr`) 연동 완료
  - `barvlDt`(도착 예정 초) 기반 실시간 ETA 동적 계산 (수신 시각 보정 포함)
  - 코레일 관할 노선 등 `barvlDt` 미제공 시 TAGO 시간표(`SubwaySttnInfoService`) 기반 Fallback
  - 서울교통공사 역간거리 JSON DB 기반 구간 소요시간 정밀 계산
  - 유령 데이터 필터링 (출발 완료 열차, 90초 이상 경과 진입/도착 데이터 제외)
  - 실시간 메시지 파싱 (`arvlMsg2` → 현재역 추출, 남은 역 수 추출)
- **버스 실시간 도착 정보:**
  - TAGO 전국 버스 도착 정보 API (`ArvlInfoInqireService`) 연동 완료
  - 경기도 전용 버스 도착 API (`busarrivalservice/v2`) 이중 조회 지원
  - ODsay 정류소 검색 API를 통한 정류소 ID 매핑 (24시간 캐싱)
  - 첫 번째 / 두 번째 버스 도착 예정 정보 동시 제공
  - 전국 주요 도시 도시코드 매핑 (서울, 경기 각 시군구, 부산, 대구, 인천 등)
  - XML/JSON 응답 자동 파싱 (`fast-xml-parser`)

### 구간별 이동 대안 선택 (✅ 구현 완료)
- 각 구간별 대중교통 / 차량 / 도보 3가지 카테고리의 복수 대안 경로를 아코디언 UI로 제공
- 사용자가 특정 대안 경로를 선택하면 해당 구간의 `selected_route` 필드에 저장 및 DB 동기화
- 경로 선택 시 지도 위 폴리라인 및 경로 안내 패널 자동 갱신

### 상세 경로 안내 패널 (✅ 구현 완료 — `RouteGuidePanel`)
- 지도 위에 오버레이되는 플로팅 패널로 선택 구간의 상세 경로 정보 표시
- **대중교통:** 노선별 step-by-step 안내 (탑승/하차 정류장, 색상 코드, 소요시간)
- **차량:** turn-by-turn 방향 안내 (우회전, 좌회전, 직진, 유턴 등 아이콘 매핑)
- **장거리 노선:** 기차/시외버스 구간별 예매 링크 인라인 제공
- 개별 step 클릭 시 해당 구간만 지도에 줌 인/하이라이트 (subType: start/end/dest)
- 「다음 이동 정보」 버튼을 통해 연속 구간 탐색 지원
- 세부 구간 탐색 네비게이션 (이전/다음 step 탐색, 현재 위치 표시)

### 여정 편집 및 관리 (구현 완료)
- 여정/장소 순서 조정 (구현 완료)
  - HTML5 기본 Drag & Drop API를 활용하여 여정 목록 및 여정 상세 내 장소 목록 순서 변경 기능 구현
  - 순서 변경 시 `verifyAndCleanRoutes()`를 통해 무효화된 `selected_route` 자동 정리
- 여정/장소 다중 선택 및 일괄 삭제 (구현 완료)
  - 편집(Edit) 모드 진입 시 체크박스를 통한 다중(Bulk) 선택 기능 적용
  - 하단 고정 버튼을 통해 선택 항목 일괄 삭제 지원
- 장소 검색 및 여정 할당 (구현 완료)
  - 여정 미선택 상태에서도 상단 검색바를 통해 장소를 검색하고, '여정 선택' 모달 UI를 통해 원하는 여정에 장소 바로 할당 지원

### 지도 연동 (✅ 구현 완료 — 고도화)
- **구간별 폴리라인 렌더링:** 교통수단 색상(버스/지하철/차량/도보)에 따른 컬러 코드 적용, 흰색 외곽선 + 본선 이중 렌더링
- **방향 화살표(Chevron):** 폴리라인 위에 일정 간격의 V자 방향 마커를 줌 레벨에 맞게 자동 생성
- **환승 안내 마커:** 대중교통 경로의 환승 지점에 환승 정보 마커 자동 배치
- **경로 횡방향 오프셋:** 동일 경로 위 다중 구간 겹침 방지를 위한 자동 평행이동 처리
- **세그먼트 포커스:** 특정 구간 클릭 시 해당 구간만 지도에 하이라이트 + 줌 인 (비포커스 구간 자동 페이드)
- **스텝 포커스:** 경로 안내 패널에서 개별 step 클릭 시 해당 노선 구간만 독립 하이라이트
- **동적 패딩:** 사이드바 및 경로 안내 패널 열림/닫힘에 따라 지도 패딩 자동 조정
- **마커 순번 표시:** 경유지 순서에 따른 번호 마커 (그라디언트 핀 아이콘)

## 4. Tech Stack & APIs (현재 구현 상태)

### 4.1 Frontend & UI
* **프레임워크:** React (Next.js 16+ App Router 기반)
* **스타일링:** Tailwind CSS (v4)
* **UI 컴포넌트:** Vanilla CSS 및 Tailwind 기반 커스텀 컴포넌트 (shadcn/ui 미도입 상태)
* **드래그 앤 드롭:** HTML5 Native Drag & Drop API 적용 완료 (여정 및 장소 목록 순서 변경 기능)
* **지도 렌더링:** react-naver-maps (적용 완료)

### 4.2 State Management & Data Fetching
* **클라이언트 상태 관리:** Zustand (적용 완료)
  * *용도:* 여정 데이터, UI 모달 상태, 경로 캐시(`directionsCache`), 포커스 세그먼트/스텝 상태 관리
  * *경로 캐싱:* 구간별 API 응답을 `Record<string, DirectionsApiResponse>` 형태로 캐싱하여 중복 호출 방지
  * *순차 호출:* ODsay API 429 동시성 제한 대비 150ms 간격 순차 호출 (`fetchJourneyDirections`)
* **서버 상태 관리 & 데이터 패칭:** 미도입 (Zustand와 Supabase Client를 통한 직접 Fetching 적용, 향후 TanStack Query 도입 검토)

### 4.3 Backend & Infrastructure
* **백엔드 & 데이터베이스:** Supabase (PostgreSQL 및 내장 Auth 활용)
* **PWA (Progressive Web App):** 미구현 (향후 도입 검토)

### 4.4 외부 APIs 연동 현황
* **대중교통 경로 탐색:** ✅ ODsay 대중교통 경로탐색 API 연동 완료 (`/api/directions` 라우트)
  - `searchPubTransPathT` + `loadLane` API 활용
  - 복수 대안 경로, 상세 궤적 좌표, 노선 색상, 환승 정보 제공
  - 장거리 노선(기차/시외버스) 경로 탐색 포함
* **차량 경로 탐색:** ✅ 네이버 Directions 5 API 연동 완료 (`/api/directions` 라우트)
  - `trafast`/`traoptimal`/`traavoidtoll` 옵션, turn-by-turn 가이드 제공
* **다중 경유지 차량 경로:** ✅ 네이버 Directions 5 프록시 API (`/api/directions-waypoints` 라우트)
  - 경유지(waypoints) 포함 차량 경로 탐색 지원
* **장소 검색:** ✅ 네이버 장소 검색 API (구현 완료 — `/api/places` 라우트 연동)
* **지하철 실시간 도착 정보:** ✅ 구현 완료 (`/api/subway/realtime` 라우트)
  - 서울시 실시간 지하철 API + TAGO 시간표 API Fallback
  - 역간거리 DB 기반 ETA 동적 계산
* **버스 실시간 도착 정보:** ✅ 구현 완료 (`/api/bus/realtime` 라우트)
  - TAGO 전국 버스 도착 API + 경기도 전용 API 이중 조회
  - ODsay 정류소 검색 API 기반 정류소 ID 매핑 (24시간 캐싱)

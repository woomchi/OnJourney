# [Project Context] On-Journey (다중 경유지 경로 최적화 서비스)

## 1. Service Overview & Philosophy
* **서비스명:** 온저니 (On-Journey)
* **브랜드 철학 및 슬로건:** "당신의 모든 이동이 온전히, 여정이 되도록."
  * 한국어 '온전히(조금도 부족함 없이 완벽하게)'와 영어 'On-Journey(여정 중에)'의 언어유희입니다. 여행이라는 단어가 주는 무거움과 "무언가를 해야 한다"는 강박을 벗어던지고, 문 밖을 나서는 순간부터 목적지에 닿기까지의 모든 평범한 이동을 하나의 소중한 여정으로 대한다는 철학을 담고 있습니다.
* **서비스 개요:** 사용자가 추가한 다수의 방문지를 바탕으로 이동 시간과 비용을 최소화하는 구간별 최적 경로 이동솔루션입니다. 방문하고자 하는 장소(n개)를 자유롭게 추가하고 직관적인 드래그 앤 드롭(Drag & Drop)으로 순서를 조정하면, 구간별 최적 경로와 이동 수단을 자동으로 생성하여 완벽히 개인화된 이동 경험을 제공합니다. 사용자가 추가하고 조정한 장소 순서는 온전히 여정의 의도로 보존되도록 합니다.

## 2. Target Use Cases
1. **🎒 통학 및 출퇴근 (반복적인 일상 경로)**
   * **문제:** 매일 같은 정류장/역을 이용하지만, 실시간 도착 정보를 보기 위해 매번 앱을 켜서 검색해야 함.
   * **해결:** 출발지와 도착지(학교/직장) 및 자주 타는 교통수단을 '여정'으로 저장. 향후 홈 화면 위젯 등을 통해 앱 실행 없이도 클릭 한 번으로 즐겨찾는 수단의 실시간 이동 시간 및 도착 정보를 즉시 확인.
2. **✈ 뚜벅이 여행객 (복잡한 다중 경로)**
   * **문제:** 자차가 없는 여행객은 낯선 지역에서 여러 관광지를 방문할 때마다 매번 지도 앱을 켜서 대중교통 경로를 새로 검색해야 함.
   * **해결:** 방문할 여러 경유지를 한 번에 저장하면 구간별 최적 경로를 하나의 여정 처럼 한 번에 제공함. A에서 B로 갈 때는 몇 번 버스를 타는지 등 '교통수단 정보'까지 함께 저장되어, 여행 중 클릭 몇 번만으로 다음 목적지로 이동할 준비를 마칠 수 있음.

## 3. Core Features (MVP)
아래 핵심 기능이 정상 작동하도록 로직을 구현해야 합니다.

여정 생성 기능
- 여정명, 기본 이동 수단, 날짜 선택을 통해 여정 생성
- 여정명: 사용자가 여정을 설명하는 텍스트 입력
- 기본 이동 수단: 대중교통/차량
- 여정 날짜 선택 : 달력 컴포넌트를 통해 여정 날짜 선택

장소 추가
- 장소 추가 버튼 혹은 상단 검색바를 통해 장소 검색 및 추가

구간별 이동 정보 제공
- n개의 장소 구간별 이동 정보를 제공
- 시간, 비용, 이동 거리, 대안 이동 수단 제공
- 도보/자전거/대중교통/차량 등 다양한 교통 수단에 대한 대안을 필요에 따라 선택

여정 편집 모드
- 장소 순서 조정
  - 드래그 앤 드롭(Drag & Drop)으로 순서를 조정
  - 순서가 조정된 장소 사이 이동 정보 갱신
- 장소 삭제
  - 각 장소 왼쪽 체크 박스를 통해 선택하여 여정에서 삭제

## 4. Tech Stack & APIs (AI Vibe Coding 최적화)

### 4.1 Frontend & UI
* **프레임워크:** React (Next.js 14+ App Router 기반)
* **스타일링:** Tailwind CSS
* **UI 컴포넌트:** shadcn/ui (Radix Primitives 기반의 고도화된 접근성 지원)
* **드래그 앤 드롭 (장소 순서 변경):** Pragmatic Drag and Drop (Atlassian)
  * *선택 이유:* `dnd-kit` 대비 극도로 가볍고 빠르며, 성능 최적화가 우수하여 모바일 환경(뚜벅이 여행객)에서 부드러운 UX를 보장함.
* **지도 렌더링:** react-naver-maps

### 4.2 State Management & Data Fetching
* **클라이언트 상태 관리:** Zustand
  * *용도:* 드래그 앤 드롭을 통한 장소 배열 순서 제어, 편집 모드 토글 등 로컬 UI 상태 관리.
* **서버 상태 관리 & 데이터 패칭:** TanStack Query (React Query v5)
  * *용도:* 네이버 지도, ODsay, 공공데이터 API의 경로 및 실시간 도착 정보 캐싱, 자동 리프레시(Polling), 로딩/에러 상태 관리.
  * *효과:* 불필요한 외부 API 호출을 최소화하여 비용을 절감하고, 한 번 조회한 여정의 빠른 로딩을 지원.

### 4.3 Backend & Infrastructure
* **백엔드 & 데이터베이스:** Supabase (PostgreSQL 및 내장 Auth 활용)
* **PWA (Progressive Web App):** Serwist (또는 `@ducanh2912/next-pwa`) 도입
  * *효과:* '홈 화면에 추가' 기능을 통해 앱 실행 없이 위젯처럼 접근하는 UX를 구현하고, 서비스 워커를 통한 여정 데이터 로컬 캐싱으로 오프라인(네트워크 불안정 환경) 조회를 지원.

### 4.4 외부 APIs 연동 계획
* **경로 탐색:** 네이버 지도 Directions 5 (차량/도보), ODsay API (대중교통)
* **장소 검색:** 네이버 장소 검색 API
* **실시간 데이터:** 공공데이터포털 (버스/지하철 실시간 도착 정보 API)

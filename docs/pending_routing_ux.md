# 향후 작업 보류 내역 (Pending Tasks)

## URL 및 라우팅 기반 상태 관리 적용 (UX 개선)

### 1. 배경 및 현재 상황
* 현재 사이드바나 바텀 시트 (검색 모드, 장소 생성, 수정 등)를 여닫는 UI 상태를 전역 상태 관리(Zustand의 `uiSlice.ts`)를 통해서만 제어하고 있음.
* **문제점:** 이로 인해 모바일이나 브라우저에서 '뒤로 가기' 버튼을 눌렀을 때, 패널이 닫히는 대신 브라우저의 뒤로 가기가 작동하여 앱(서비스) 자체를 이탈하게 되는 심각한 사용자 경험(UX) 문제가 발생할 우려가 있음.

### 2. 목표 아키텍처 (네이버 지도 방식)
네이버 지도와 같이 **URL Path 및 Query Parameter 연동 방식**을 도입하여 해결하기로 결정.
* **장점 1 (뒤로 가기 연동):** URL 파라미터가 변경되므로 브라우저 히스토리가 쌓임. 사용자가 뒤로 가기를 누르면 파라미터 이전 상태로 URL이 변경되며 이를 감지해 자연스럽게 바텀 시트가 닫힘.
* **장점 2 (공유하기/Deep Linking):** 특정 장소, 혹은 검색 결과가 URL에 직접 반영(`예: /search/강남역` 혹은 `?mode=search`)되므로 다른 사용자에게 링크를 공유했을 때 동일한 UI와 화면이 열릴 수 있음 (지도 서비스의 핵심 기능).

### 3. 작업 보류 사유
* 현재는 UI 배치 및 기능의 신규 개발/수정이 빈번하게 일어나고 있는 초기 단계임.
* 각 UI 상태를 모두 URL 라우터에 연결해두면 컴포넌트 수정 시마다 라우팅을 함께 관리해야 하므로 개발 속도 저하 및 오버헤드가 발생할 수 있음.
* **결론:** 기능 구현 및 UI가 일차적으로 안정화(Stable)된 시점에 각 모달 및 바텀 시트 상태를 Next.js의 URL 파라미터 혹은 Path와 연동하는 작업을 일괄 진행하기로 함.

### 4. 나중에 진행할 구체적 작업 항목
- [ ] `uiSlice.ts` 의 boolean 상태들 (`isSearchMode`, `isCreateFormOpen` 등)을 Next.js Router (query/param) 기반으로 마이그레이션.
- [ ] `useEffect` 혹은 Next.js의 `useSearchParams`, `usePathname`을 활용하여 URL 변화에 따라 UI 렌더링 동기화.
- [ ] 데스크톱 및 모바일 PWA 환경에서 '뒤로 가기(Back)' 이벤트 시 의도한 대로 UI가 닫히는지 테스트.

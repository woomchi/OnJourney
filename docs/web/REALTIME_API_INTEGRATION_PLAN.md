# 실시간 대중교통 데이터 연동 및 UI 반영 계획서

본 문서는 추후 공공데이터포털(BIS 등)의 실시간 도착 정보를 OnJourney 앱의 대안 경로 패널에 연동하기 위한 아키텍처 및 UI/UX 실행 계획입니다.

## 1. 아키텍처 및 통신 전략 (BFF 패턴)
프론트엔드에서 공공데이터포털 API를 직접 호출하면 CORS 이슈, API Key 노출, 다중 호출 부하가 발생합니다. 이를 방지하기 위해 Next.js의 API Route(BFF - Backend For Frontend)를 활용합니다.

- **Frontend (`AlternativeRoutePanel.tsx`)**: 
  - `activeSubTab === '추천'`일 때, 상위 핵심 경로들의 출발 정류장/수단 정보를 묶어 Next.js API(`/api/realtime`)로 한 번에 요청을 보냅니다.
- **Backend (`src/app/api/realtime/route.ts` 등)**:
  - 프론트엔드로부터 받은 N개의 수단 정보를 바탕으로 공공데이터 API를 비동기 병렬 호출(`Promise.all`)합니다.
  - 서버 단에서 데이터 캐싱을 수행하여 응답 속도를 높이고 API 일일 트래픽 제한을 방어합니다.
  - 정제된 응답(`{ routeId: { status: '지연', minutesLeft: 5 }, ... }`)을 프론트엔드로 반환합니다.

## 2. 상태 관리 및 타겟팅 호출 (Targeted Curation)
무분별한 실시간 API 호출 트래픽을 방지합니다.

- **상태 관리**: 
  - `realtimeData`: 각 대안 경로 ID를 키로 하여 실시간 상태를 저장.
  - `isRealtimeLoading`: 비동기 로딩 제어용 상태.
- **호출 조건**:
  - 패널 마운트 시 기본 활성화되는 `[추천]` 탭의 상위 경로 5개 내외에 대해서만 백그라운드 자동 호출을 진행합니다.
  - 스크롤이 길어지는 일반 탭(`[전체]`, `[지하철]` 등)은 무조건적인 호출을 막고 쾌적한 렌더링을 유지합니다.

## 3. UI/UX: 레이아웃 시프트 없는 비동기 뱃지(Badge)
실시간 지연 시간(예: 10분 지연)을 전체 소요 시간에 무리하게 단순 덧셈(+)하여 경로 순위를 바꾸면 정합성이 깨지고 화면이 널뛰는(Flickering) 치명적 문제가 발생합니다.

- **해결책 (비동기 뱃지)**:
  - 경로 카드 리스트의 뼈대와 시간 수치는 원래의 순서대로 즉시 렌더링하여 로딩 딜레이를 없앱니다.
  - 경로 카드 내에 실시간 정보 전용 영역을 두고, 로딩 중일 때는 `스켈레톤(반짝이는 회색 상자)`을 표시합니다.
  - 실시간 데이터 연동이 완료되면 `[곧 도착 🚌]`, `[10분 지연 ⚠️]` 등 가시성 높은 컬러 뱃지로 전환합니다.
  - 이를 통해 유저는 혼란 없이 지연 중인 수단을 직관적으로 피할 수 있습니다.

- [ ] 2단계: 프론트엔드에서 묶음 API 호출 함수 작성 및 상태(`realtimeData`) 연결
- [ ] 3단계: `AlternativeRoutePanel.tsx` 내 스켈레톤 및 컬러 뱃지 UI 추가
- [ ] 4단계: `추천` 탭 자동 연동 및 실시간 데이터 업데이트 테스트
